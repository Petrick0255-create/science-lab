처음 한 번, Google 연결하기

이 앱은 정적 파일만으로 동작합니다. Gemini 키는 대본 생성에, Google OAuth 클라이언트 ID는 주제 DB 로그인에 사용합니다. 두 값은 서로 다릅니다.

1. Gemini API 키

Google AI Studio에서 키를 준비해 앱의 ‘연결 설정’에 입력하고 저장합니다. ‘모델 접근 확인’을 누르면 내 키로 쓸 수 있는 모델을 확인합니다.

2. Google 로그인용 클라이언트 ID

  1. Google Cloud Console에서 사용할 프로젝트를 선택하고 Google Sheets API를 사용 설정합니다.
  2. Google Auth Platform에서 앱 이름과 지원 이메일 등 동의 화면을 설정합니다. 개인용이라면 외부 앱의 테스트 상태로 두고, DB를 사용할 Google 계정을 테스트 사용자로 추가합니다.
  3. 데이터 액세스에 https://www.googleapis.com/auth/spreadsheets 범위를 추가합니다. 이 권한은 계정의 Sheets 읽기·쓰기를 허용합니다. 앱 코드는 설정된 주제 DB 한 개에만 요청합니다.
  4. 클라이언트에서 웹 애플리케이션 유형의 OAuth 클라이언트를 만듭니다. 승인된 JavaScript 원본에 앱이 열리는 원본 주소를 등록합니다. GitHub Pages라면 https://petrick0255-create.github.io, 로컬이라면 http://localhost:8080입니다. 실제 커스텀 도메인을 쓰면 그 원본도 추가합니다. 경로는 넣지 않습니다.
  5. …apps.googleusercontent.com 형식의 클라이언트 ID를 앱에 저장합니다. 클라이언트 보안 비밀은 사용하지 않으며 입력할 곳도 없습니다.
  6. ‘Google DB 연결’을 눌러 생성된 시트에 접근 가능한 계정으로 로그인합니다. 팝업을 허용하고 Sheets 권한을 승인합니다.

3. 대본 만들기

주제 추천 → 다섯 주제 중 선택 또는 자유 입력 → 모델·낭독 속도 선택 → 1분 대본 만들기. 완성 후 DB에 자동 저장합니다. 저장에 실패해도 브라우저에 남으며, 다시 연결한 뒤 ‘DB 저장 / 재시도’를 누릅니다. 편집한 대본은 원본을 남긴 새 기록으로 저장합니다.

연결 문제

  • origin_mismatch: 브라우저 주소의 원본과 승인된 JavaScript 원본이 같은지 확인합니다.
  • Google 403: Sheets API 사용 설정, 테스트 사용자 등록, Sheets 권한 승인, 시트 접근 권한을 확인합니다.
  • Gemini 429: API 사용량 또는 요금제 한도입니다. 잠시 기다린 뒤 다시 시도합니다.
  • Google 로그인 만료: Google DB 연결을 다시 누릅니다. 로그인 토큰은 브라우저 저장소에 남기지 않습니다.
  • 파일 더블클릭(file://)은 지원하지 않습니다. HTTP 로컬 서버 또는 HTTPS 정적 호스팅을 사용합니다.

데이터와 키

Gemini 키는 이 원본의 localStorage에 저장되고 Gemini API 요청 헤더로만 전송됩니다. 키는 시트·GitHub에 기록하지 않습니다. 주제 이력의 제목·대표개념과 요청 주제는 중복 방지 및 대본 생성을 위해 Gemini에 전달됩니다. 생성 대본은 Google Sheet와 브라우저의 저장 대기 목록에 보관됩니다.

DB는 지정한 Drive 폴더의 기존 공유 권한을 그대로 상속합니다. 현재 폴더는 링크가 있는 사용자의 편집이 허용된 상태입니다.
