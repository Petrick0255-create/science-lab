# v24: 다른 문항 그림 혼입 및 캡처 잘림 수정

기존 글자 추출 지시문·요청·응답 처리·첨자·검증은 변경하지 않았습니다. 그림 크기와 텍스트 배치 방식도 유지합니다.

## 수정 내용

- PDF 안에 저장된 실제 이미지 영역을 우선 찾습니다. 이 단계에는 AI 좌표 요청이 필요하지 않습니다.
- 페이지의 문항 번호, 좌우 단, 다음 문항의 시작 위치로 그림의 소속을 결정합니다.
- 한 문항만 다시 찾아도 이웃 문항의 경계를 확인하므로 5번에 오른쪽 7번 그림을 넣지 않습니다.
- 조각으로 나뉘어 저장된 한 그림은 합쳐서 전체를 캡처합니다.
- 문항이나 좌우 단 경계를 넘는 영역은 경계에서 잘라 넣지 않고 제외합니다.
- 직접 추출할 그림이 없으면 AI 영역 찾기를 시도하지만, 이 경우에도 문항 소속을 확인할 수 있는 영역만 넣습니다. 확인할 수 없는 그림은 PDF 직접 캡처로 추가하세요.
- 원본/색상 반전, 캡처 범위 수정, 이미지 포함/제외는 유지합니다.

제공된 예시 PDF로 실제 내부 그림 탐지를 실행하고 3·4·5·7번 캡처를 화면에서 확인했습니다. 5번 개미 그림과 7번 전체 대화 그림의 연결·잘림을 확인했고, 총 33개 캡처 영역의 이미지 포함 PPT 저장을 테스트했습니다. 테스트에서 기존 글자 분석 응답은 대체했지만, 그림 좌표는 대체하지 않았습니다. 문항 혼입 방지 등을 포함한 27개 자동 검사도 통과했습니다.

모든 PDF를 같은 방식으로 찾을 수 있는 것은 아닙니다. 스캔 PDF나 문항 번호를 읽을 수 없는 PDF는 자동 소속 확인이 어려워 직접 캡처가 필요할 수 있습니다. 그림 영역을 임의로 다른 문항에 연결하는 대신 자동 삽입을 보류합니다.

## 배포

기존 science-lab 프로젝트의 `programs/exam-pdf-to-ppt/`에 이 폴더의 **index.html과 assets 전체**를 덮어쓰고 기존 방식으로 배포하세요. PDF 렌더러가 있는 `assets/pdfjs/`도 포함해야 합니다.

앱 전용 Worker라면 기존 Worker 이름을 확인하고 압축 해제 폴더에서 다음을 실행합니다.

```powershell
npm ci
npx wrangler login
npx wrangler deploy
```

기존 API 키와 로그인 설정을 그대로 사용하며, Worker 코드는 바꾸지 않았습니다. 다중 프로그램 Worker의 설정을 이 앱 전용 설정으로 덮어쓰지 마세요.

배포 후 Ctrl+F5로 새로고침하여 **v24**를 확인하고, PDF를 다시 분석하세요. 이미 잘못 캡처된 v23 결과가 자동 교정되는 것은 아닙니다.

## 수정 파일

- `assets/index-v24.js`: 실제 배포 앱 소스
- `assets/image-tools-v24.js`: 캡처·반전·그림 편집
- `assets/pdf-figures.js`: PDF 내부 이미지 탐지, 문항 연결, 조각 합치기
- `npm run build:v24`: 압축 파일 및 Worker 정적 자산 갱신
- `npm test`: 자동 검사

기존 ZIP의 `src/`와 `shared/`는 배포 번들보다 오래된 레이아웃이므로, 실제 배포 코드 수정은 위 파일들에서 진행합니다.
